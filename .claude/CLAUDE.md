## AWS resources

The data lake uses a medallion layout with one S3 bucket per layer, named `al-test-dl-<layer>`. All buckets are in us-west-2, with public access blocked, SSE-S3 (AES-256) encryption, ownership set to BucketOwnerEnforced and TLS-only bucket policies. Since 2026-11-17, staging, bronze, silver, gold and serving are **versioned** (staging, bronze, silver and gold were imported into CloudFormation stack `FinoraDlStorage`, RemovalPolicy RETAIN).

| Layer | Bucket | Purpose |
|---|---|---|
| Staging | `al-test-dl-staging` | Landing zone: raw CSV uploads exactly as received. EventBridge notifications on; an Object Created event under `transactions/`, `industry/` or `s_and_m/` starts `finora-dl-ingest`. Read-only for every pipeline |
| Bronze | `al-test-dl-bronze` | Byte-faithful CSV plus exactly ONE new column, `_ingested_at` (UTC): `<dataset_id>/ingest_date=YYYY-MM-DD/<dataset_id>__<ts>__<sha8>.csv`; write-once manifests `_manifests/<dataset>/<sha256>.json`; current snapshot `_current/<dataset>.json`; delivery log `_deliveries/`; per-run ingest result `_runs/run_id=<id>/ingest.json` (used to record failed runs) |

Each run is a full rebuild: one snapshot per table, tagged `<run_id>` (time travel: `FOR VERSION AS OF <snapshot_id>` in Athena, `VERSION AS OF '<run_id>'` in Spark; ids per run in the run report). `hr_sensitive` is a boolean partition column on sm_spend, restatement_log, findings and excluded_rows. | Serving | `al-test-dl-serving` | DQ dashboard snapshots: `dq/runs/<run_id>/summary.json` and `records/<rule_id>/<dataset>/page-<n>.json`, `dq/runs.json`, `dq/trend.json`, and the `dq/latest.json` pointer (written last).
